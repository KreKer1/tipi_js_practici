## 4. Модель данных и функции

Задача - объект `{ id, title, completed, priority }`.

- `id` - положительное безопасное целое число (строка "4" не подходит).
- `title` - строка, после `trim()` длина от 1 до 100.
- `completed` - `true`/`false`, у новой задачи всегда `false`.
- `priority` - только `"low"`, `"medium"`, `"high"` (по умолчанию `"medium"`).

Файлы:
- `src/data.js` - общий набор `demoTasks` и мой вариант;
- `src/task-service.js` - 9 функций, без `console.log` и без глобального списка;
- `src/main.js` - сценарии и вывод в консоль.

При ошибке функции возвращают `{ ok: false, error: "..." }`, при успехе -
`{ ok: true, task }` (создание) или `{ ok: true, tasks: новыйМассив }` (изменения).

Почему id не равен индексу: id - это "имя" задачи, а индекс - её место в массиве.
После удаления индексы сдвигаются, а id остаются прежними. Например, задача `id = 4` лежит по индексу 1.

Почему getTaskStats возвращает число: расчёты должны быть с числом, а `toFixed(1)` даёт строку,
поэтому округляю только при выводе в `main.js`.

Какие объекты копируются при изменении: создаётся новый массив (`map`/`filter`/spread) и новый
объект только для изменённой задачи (`{ ...task, completed }`). Остальные задачи переиспользуются,
исходный массив не меняется.
